# 5. 评测地图与指标定义

[概览](README.md) · [数据与实验设置](design.md) · [Process-SFT](process_sft.md) · [Final-SFT](final_sft.md) · [GRPO](grpo.md) · **评测方法** · [逐题记录](records.md) · [名词与指标解释](glossary.md)

本页说明三项评测分别比较什么，以及怎样阅读覆盖、质量、答案和失败指标。完整结果由各自报告承接；不同题集和评分尺度分开报告，不合成一个总准确率。

Process负责检索与证据整理，**答案生成模块（Final）**负责结合原问题和实际交付材料撰写回答。这里的**基座答案生成器（Base Final）**使用同一Qwen3-8B并禁用本项目adapter；它在Process-GRPO中不更新参数，仍会随输入材料生成不同答案。

## 实验分组与历史边界

| 评测 | 固定什么 | 比较什么 | 完整记录与报告 |
|---|---|---|---|
| **[Process开发对照评测 · HealthBench50](experiments/process_grpo_20261026/README.md)** | 同一题集、基座答案生成器；Base/SFT与GRPO的过程运行配置有差异 | 开发阶段的证据交付、State、失败与checkpoint表现 | 50题、200条 |
| **[跨基准验证评测 · HealthBench50＋MedBrowseComp50](experiments/newbench_20261028/README.md)** | 相同runtime、预算、检索与答案生成配置 | 四种Process策略各自重新获取证据、交付材料并生成答案 | 100题、400条 |
| **[Final模块对照评测 · dev100](experiments/final_sft_dev100/README.md)** | 每题同一份实际答案请求快照 | Base Final与Final-SFT 1/1.5/2轮如何使用相同材料回答 | 100题、400条 |

两个HealthBench50是不同的50题子集，Q编号只在各自评测内有效。Process开发对照已用于诊断与checkpoint比较，不作为独立未见测试；dev100也是开发验证。跨基准题在该轮生成前选定，现已用于分析，后续不能继续声称从未接触。

**参数不更新与输入固定是两种约束：** 四组Process评测使用相同的答案模块参数，但各组可能交付不同证据，因此答案也可能不同；dev100则让不同答案模块使用每题同一份实际请求，不重新检索。当前Process交付/可靠性候选与答案模块选型，应分别查看对应评测的结果和限制。

## 表格字段速查

| 字段 | 含义 |
|---|---|
| 交付覆盖% | 适用证据覆盖了多少原题内容点；不是检索成功率 |
| P1 / P2 / P3 / P4 | 覆盖40、State30、Checklist20、决策10分 |
| 原始P | 四项相加，满分100 |
| 质量R | 在P基础上应用重大/致命/失败规则，范围0–1 |
| HB | 对最终答案满足原生rubric的加权评分，可为负；不是医学准确率 |
| 重大 | 核心证据、对象、范围或交接被实质破坏，不等于程序中断 |
| 模型失败 | Process合同错误未能恢复并终止；与仅Final失败分开 |


## Process怎么评分

每题先按原问题确定内容点CP，同题不同模型共用，不强凑数量，不按检索结果倒推要求，不把HealthBench隐藏rubric输入Agent。评分查看实际首个Final请求及其可解析无损证据引用，不用更大的存档冒充已交付材料。

| 分项 | 权重 | 核验内容 |
|---|---:|---|
| P1 交付覆盖 | 40 | 每个CP按0/1/2评分；40×sum(CP)/(2×CP数) |
| P2 State | 30 | 事实忠实、E绑定/适用范围、更新/缺口各10/5/0 |
| P3 Checklist | 20 | 原问题事实/范围、核心需求覆盖各10/5/0 |
| P4 决策与停止 | 10 | 服务缺口与重复/停止两个子项，各最多5分 |

CP的2分是适用交付正文直接覆盖所问关系，1分为部分/间接但有帮助，0分为缺失或不适用。能如实回答“证据不确定”的材料可以有用；没有命中不等于证明研究不存在。每点私有记录包含支持E、原句、边界和理由，公开页保留摘要。

E正确且实际已交付，但State漏写或误读：保留P1的信息收益，在P2扣相应错误。只在未交付存档出现的内容另记发现收益，不能补P1。链路长、E多、State更新多不自动加扣分。


## 原始分P与质量值R

普通引用标签写错、单次无效重复或局部缺口问题按相关分项扣分；只有核心证据基础被实质破坏，才判重大。包括错误实体/剂量/方向、无依据关键事实、关键State误读、严重Checklist偏题，以及重复挤占预算造成核心交付缺失。合法换源、重读新focus、仍有效的State保留不直接判错。

原始P=P1+P2+P3+P4。正常R=P/100；存在未纠正重大非致命Process错误则R=0.49×P/100，同条只乘一次；致命或明确Process模型任务失败R=0。工程损坏或交付身份不明R=null并留置；不能把未知工程问题当模型零分。已纠正且无残留的中间错误记录恢复，不判终点重大。

高质量须R≥0.75且无重大、致命、模型任务失败或工程留置。Final-only失败不直接把Process置0。Process模型失败没有真实Final交付时P1为0，失败前发现材料保留诊断。


## HealthBench怎样评分

使用原题原生rubric和原始权重，由服务器qwen3.7-max逐项判断；每题加权分可为负，失败/未评分为空。不同模型主比较使用同题有评分配对，并单独列出全量失败；不把缺失伪造为0，也不把成功子集替代全量工程结果。

Process评分不读取新Final答案或Judge分来决定P1；HB分单独报告，不加入本轮GRPO训练奖励。交付覆盖、P、R、HB不是同一种分数，不把它们都称为准确率。

## MedBrowseComp与Final模块怎样评分

MedBrowseComp使用服务器qwen3.7-max替代Judge检查最终答案与参考是否语义等价，单条0/1，正确数除以有效评分数得到匹配准确率；失败保留未评分，NA与NOT LISTED按题面及参考约定处理。它不采用HealthBench的加权rubric，也不与HB合成均分；该题集的具体适配见[跨基准评分口径](experiments/newbench_20261028/protocol.md)。

Final模块对照按证据利用40%、问题相关性30%、忠实性20%、不确定性校准10%进行项目审核；没有已打开证据时证据利用不适用并重新归一。其格式有效分母、同题有效配对和共同有效题另列，不采用HealthBench评分，详见[Final评分方法与结果](final_sft.md#答案如何评分)。

## 审核方式与边界

同题各组共用预先确定的CP；实际交付与State判断分开审阅，不因轨迹长或更新多机械扣分。没有State输出只说明未观测到该次判断，不能解释为State能力通过；明确Process模型失败仍按R0保留。工程不可信时留置，不把未知损坏当模型零分。

Process审核不读取Final答案或Judge分来决定P1。主审源核验、多审阅者盲读与交叉复核仍属于AI审阅，没有独立临床金标准或重复裁判实验。每项报告分别说明实际盲审程度、校准与污染/题面敏感性边界，见[开发对照审核](experiments/process_grpo_20261026/README.md#评分与审核范围)、[跨基准核查](experiments/newbench_20261028/README.md#数据与边界核查)和[Final审阅方式](final_sft.md#答案如何评分)。

答案逐题胜负只比较双方有评分的题，同时完整列出全部失败；Process全题比较保留明确模型失败R0。bootstrap区间只反映固定本次生成与Judge结果下的题目抽样，不包含换seed重新生成或重复裁判波动。

## 完整记录与可复算文件

所有成功、失败和重大记录都保留，入口见[逐题索引](records.md)。三项报告附各自CSV、JSON和复算入口；公开摘要可核查评分理由与统计，完整批量答卷、实际请求、逐字证据及rubric回执保存在私有归档。少量真实输出与短摘录按[案例页](../../examples/version3_cases/README.md)所述范围公开。

来源、哈希和算术检查属于工程核验，不能据此认证医学质量。早期四组消融计划见[历史归档](archive/evaluation_initial_plan.md)，不将其38/20题或六checkpoint候选设计当作已执行结果。
