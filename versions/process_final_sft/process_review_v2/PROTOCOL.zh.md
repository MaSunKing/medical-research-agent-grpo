# Process重评 v2（评分前冻结）

范围：原始972 checkpoint1322与Base的同一50题，全部100条最新attempt。原始记录和v1只读；不运行模型、API、训练或补采。单次离线Codex审核，不是独立临床专家认证，也不是官方HealthBench评分。

## 共同需求与证据覆盖（主指标）

每题先仅按原始用户问题定义1至数个必要需求F1…，两组共用，权重相同；不按模型Checklist、HealthBench隐藏rubric、检索得到什么倒推需求。原题含多个明确子问题时拆开，避免人为膨胀。每个需求0=没有适用已打开证据；1=部分覆盖或间接证据；2=直接适用材料覆盖所问关系，包括如实体现不确定性的材料。来源质量、适用人群、干预/比较/结局、时效局限必须文字注明。直接不等于可靠、确定或证明因果；不在此声称研究自身有效性。

每题覆盖率=sum(F分)/(2*F数)*100。所有50题各自先归一再取均值；没有打开证据记0，包括失败前无证据。失败前有证据仍评，不能将失败整题机械归零。每题每组登记全部E ID的直接/部分/背景/噪声/重复角色和F映射，保留来源引用。重复/重叠不增加覆盖；补充事实、独立佐证候选或冲突发现另记正收益，不按E条数计分。没有研究命中不证明研究不存在；对于询问证据是否成立的问题，适用的否定或不确定证据可获分。

## State忠实度（分开，不与覆盖加权成总分）

主要评最终State对已打开证据的事实忠实、证据绑定、更新完整性，每项0/1/2：2=无已证实缺陷；1=局部不充分；0=关键错误或系统性遗漏。每项给具体理由与E/R引用。State率=sum(三项)/6*100，仅有实际已接受State调用时计算；无调用记not_observed/null，不补零、不声称State正确。初始missing且没证据不算更新错误。State中的direct表示关系直接被讨论而非证据确定性；direct+gap不自动错误。缺口合理保留不扣。最终已纠正的中间误读单列，不等同最终仍错误。

事实忠实：原文数字、方向、关系、适用对象是否被正确保留；证据绑定：所引用E是否存在且适用于相应断言；更新完整性：已取得的关键证据是否被State吸收，区分漏写与没找到。取得证据但漏写只能影响更新完整性，不能把证据覆盖再扣成没取得。同一根因不跨多个State项重复扣，除非有不同可指认缺陷。空更新不自动扣分。

## 工程、行为与Final

全部100条记录Process硬失败、降级、正常终止、仅Final失败。Final失败不扣Process覆盖或State分。正常预算结束、调用长、重复一次均不自动扣质量分。执行次数、重复query次数/深度、缓存、无Browse、失败反馈后改策作为诊断另列；无失败反馈不宣称纠错能力已验证。相同channel+casefold/空白归一query才算完全重复。

每条保留：需求分及理由/E引用、全部E角色、State三项分/理由、具体问题文字、优点与局限、原始身份哈希。汇总主表覆盖所有50题每组；State报告可观察分母及缺失原因；50同题覆盖差全部纳入。提供逐题比较和工程失败清单，不只选成功配对。HB分独立原样保留，缺失不填0。
