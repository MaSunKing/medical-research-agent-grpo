# 固定Base Final下的Process-GRPO：训练与50题评测

截至2026-10-26：100题×4条真实轨迹已采集，99个可用题组完成25批离线更新；第13批和第25批各重新运行50题。以下将历史Base/SFT与新GRPO分开说明，所有组均接同一个冻结Base Final。

## 1. 从Base到GRPO的实验链

| 阶段 | 已执行内容 | 角色边界 |
|---|---|---|
| Base | Qwen/Qwen3-8B，以bitsandbytes NF4双重量化、BF16计算加载 | Base对照禁用本项目adapter |
| Process-SFT | 972题、10575个阶段目标、1322次更新 | 只监督Checklist、Decision、State等Process输出 |
| Final-SFT探索 | gold600固定500 train / 100 dev，独立Final LoRA训练至1、1.5、2轮；dev100含Base共400条评审 | 未显示优于Base Final，后续GRPO继续冻结Base Final |
| GRPO采集 | 50道原train500短题＋50道LiveQA历史Train-1长题，每题4条，共400条 | 不使用dev100和HealthBench训练；训练题与旧50题ID/规范化文本重叠为0 |
| 本地奖励 | 全400条保留评分与问题文字；1组工程留置，99组可用 | 以实际交付Pre-final与Process行为为奖励，不混合Final答案分 |
| GRPO更新 | 从原972 checkpoint1322继续，仅更新Process LoRA；25批、单次遍历 | 第13批是中途checkpoint，第25批是本轮完成checkpoint |
| 本次评测 | 两个GRPO checkpoint各重新运行50题；历史Base/SFT各50条复用 | 200条Process均有逐题记录，188个有效HB分，未评分不补零 |

GRPO13尚未走完全部训练题组时保存，但整个正式训练已经完成25批。不能把中途checkpoint表现较好解释为任务漏训，也不能仅凭两个点认定过拟合。

## 4. 重复Search与失败

| 指标 | Base | SFT | GRPO13 | GRPO25 |
|---|---:|---:|---:|---:|
| Search动作 | 71 | 92 | 103 | 120 |
| 完全相同查询的额外动作 | 11 | 18 | **0** | **0** |
| 有该类重复的轨迹 | 11/50 | 7/50 | **0/50** | **0/50** |
| 上述重复实际再次发起外部搜索 | 0 | 0 | 0 | 0 |

口径为同题、同channel、大小写/空白规范化后相同query，首次之外的已执行/缓存动作；不把非法决策格式修复算重复。旧29次均命中缓存，不能说额外消耗29次Serper请求；缓存重选也不必然无效，严重程度另看是否获取新内容、是否挤占核心任务。该表未测语义换词后的冗余。

新GRPO13在Q22出现Process合同失败，State多次非法字段/无效JSON未恢复，Final未启动，HB留空；GRPO25无Process硬失败。模型失败和内容错误仍存在，完成率不能代替语义可靠性。新两组各20条重大未纠正问题，40条中37条涉及State，7条涉及Checklist，可重叠；例如范围/剂量误读、否认已有证据、无依据补充事实。

## 5. 如何解释与选择

GRPO13相对历史SFT交付覆盖高13.92个百分点，GRPO25高6.00个百分点，且两组本次没有完全相同Search重复。更充分的适用证据有利于回答，但不等于Final必然利用正确。综合R几乎持平，State错误尚未得到明确改善。

当前优先保留GRPO13为内容效果候选，保留GRPO25作为完成率更好的对照；不宣称13已统计优于25，也不因25覆盖下降就断定训练越多越差。历史与新运行的输出头、种子及JSON修正存在差异，不能将全部历史差值归因于GRPO权重。

旧50题与本轮100道GRPO训练题的ID及规范化文本均不重叠，但已被用于开发诊断、规则讨论和checkpoint选择，因此不是独立未见测试。新题同配置Base/SFT/GRPO13验证尚未启动；不在此预报结果。
