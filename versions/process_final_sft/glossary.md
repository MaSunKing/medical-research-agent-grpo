# 概念与术语：怎样读懂这组实验

[版本三概览](README.md) · [三项评测](evaluation.md) · [逐题记录](records.md) · [工程流程](engineering.md) · [GRPO算法](grpo.md)

这里解释本仓库使用的名称和表格字段。相同英文词在模型训练、工程运行和内容评分中可能指不同对象，阅读时先确认“比较什么、固定什么、分母是什么”。

<a id="evaluations"></a>

## 三项评测各自回答什么

| 名称 | 要回答的问题 | 比较对象与控制方式 |
|---|---|---|
| **Process开发对照评测 · HealthBench50** | Process训练后，证据获取、交付和答案表现怎样变化？ | 50题、四组共200条；用于开发诊断及checkpoint比较。历史Base/SFT与后续GRPO运行配置有差异，保留其描述性对照边界 |
| **跨基准验证评测 · HealthBench50＋MedBrowseComp50** | 在另一批题和相同运行配置下，四种Process策略表现怎样？ | 两种benchmark各50题，四组共400条；每组重新检索，Final固定Base。结果分别报告，不合成一个总准确率 |
| **Final模块对照评测 · dev100** | 输入相同时，训练Final是否更会使用证据回答？ | 每题同一份冻结Final输入，Base Final与Final-SFT的1/1.5/2轮checkpoint比较，共400条答案记录 |

**benchmark**是提供问题及评价依据的基准数据集；**评测方案**还规定选哪些题、模型如何运行、谁来评分和怎样统计。本项目的两个50题子集不代表完整官方榜单。**离线／合成测试**核验代码合同、恢复和计算等工程行为，不评价医学回答水平。

两个评测名称里的**HealthBench50是不同的50题子集**。编号仅在各自评测内有效，例如开发对照的Q01与跨基准验证的Q01不是同一道题；应按评测名称和原始题目ID识别记录。

**开发对照**允许用于诊断和选型，因此不再是独立未见测试；dev100中的`dev`也是开发验证的意思。跨基准题在本轮生成前选定，已经用于分析后，后续实验不能继续把它称为从未接触的测试。选题、排重及适用范围见[实验设置](experiments/newbench_20261028/setup.md)。

<a id="models"></a>

## 模型名、checkpoint和轨迹

| 术语 | 在本项目中的含义 |
|---|---|
| **Base** | `Qwen/Qwen3-8B`以bitsandbytes 4-bit NF4双重量化加载、BF16计算，不启用本项目LoRA。不是另一份名为`Qwen3-8B-Base`的模型，也不是未量化对照 |
| **Process-SFT / SFT** | 同一基座加原972题监督训练得到的Process LoRA（checkpoint1322）；在Process四组表中，`SFT`均指它 |
| **Final-SFT** | 同一基座加独立训练的Final LoRA；只在Final模块对照中与Base Final比较，不等同于Process-SFT |
| **Process-GRPO** | 从Process-SFT继续更新Process LoRA；本轮Final保持冻结Base。使用真实轨迹的相对奖励，不在更新循环中再次检索或调用裁判 |
| **GRPO13 / GRPO25** | 分别完成第13／25个更新批次的checkpoint。13批覆盖固定顺序中的前52个可用题组，25批完成全部99组；数字不是epoch数 |
| **checkpoint（断点）** | 某次更新后保存的模型状态；能否继续训练还取决于optimizer、进度和身份等恢复材料，只有adapter文件不等于完整续训断点 |
| **epoch（轮）** | 对训练集完整遍历一次。Final-SFT的1／1.5／2轮是训练进度，不能与GRPO13／25的批次数直接比较 |
| **rollout（轨迹）** | 同一策略针对一题的一次真实运行，包含阶段输出、工具结果、状态及终态；不只是最终答案 |
| **题组 / arm（组别）** | 训练题组是同一题的4条rollout；评测arm是Base、SFT、GRPO13或GRPO25中的一种模型条件 |

两个“100题×4”不要混淆：**GRPO采集是同一个初始策略每题采4条，用于同题相对学习；跨基准评测是每题由四种策略各跑1条，用于比较模型。** 评测四组不是训练用的4个rollout，不据此计算训练优势。

LoRA是叠加在冻结基座上的少量可训练参数；QLoRA表示在量化基座上训练LoRA。**冻结**指相应参数在该实验中不更新，不表示它每次输出都完全相同；生成还受输入和采样配置影响。具体加载、参数与更新方法见[GRPO章节](grpo.md)。

**completion-only loss与mask：** SFT只计算当前合法assistant目标片段的损失；原问题、历史和工具正文可作为输入读取，但相应位置不计loss。Final-SFT的目标是答案与EOS，Process-SFT的目标是Checklist／Decision／State；mask输入不等于模型不能学习利用输入。

**行为概率、重放与概率校正：** 采集时保存实际生成token的行为概率；训练前用冻结策略重算训练路径的概率，更新时再计算当前策略概率。同一权重在逐token生成与整段前向中可能有数值差异，因此用固定校正权重处理其对更新的影响，再对当前／初始训练路径概率比做PPO式裁剪。重放只计算已保存token的概率，不是重新检索或重新生成答案；完整公式见[算法说明](grpo.md)。

<a id="agent"></a>

## Agent阶段与证据身份

| 术语 | 具体做什么 |
|---|---|
| **Process** | Final之前的需求拆解、Search／Browse决策、State支持判断及停止；负责获取并交付材料 |
| **Checklist** | 模型把原问题拆成需要核验的需求，程序分配`R1`、`R2`等稳定ID；原题仍保留 |
| **Decision** | 根据当前缺口选择一次Search、Browse或Stop；一次工具动作绑定1–2个需求 |
| **Search / Browse** | Search发现可选来源和预览；Browse实际读取并返回正文片段。搜索摘要或标题不会自动成为已打开证据 |
| **reading_focus** | 本次Browse要查找的内容，每次独立处理，不累计。其检索投影预算与证据正文预算分开，见[长度约束说明](engineering.md#5-browse与reading_focus围绕本次缺口读取来源) |
| **State** | 按需求记录支持程度、证据ID、缺口和冲突。`missing / partial / direct`是模型判断，程序检查ID和结构，不保证内容判断正确 |
| **Pre-Final / 实际Final输入** | PreFinal汇集完整状态、证据与历史；ContextBuilder另按预算构建实际Final请求。完整问答使用请求生成答案，采集模式另存输入快照；完整归档中未进入请求的正文不能算已交付 |
| **Final** | 根据实际可见材料综合回答的独立角色；在Process四组评测中统一采用冻结Base Final |

**三个身份层不要混用：** `R1`等是待解决的需求；`A/B/...`是每题稳定的来源简称，后面对应`PMID:`、`S2:`或`WEB:`身份；`E1/E2/...`是已打开、可定位的证据片段。一个来源可产生多个E；E多不等于独立来源或有效事实更多。`chunk_id`标识文档内片段，原文区间与哈希用于追溯。

**LangGraph**负责节点和路由；**ReAct**描述“决策—工具—观察—再决策”的循环；**MCP**提供工具调用边界。它们是编排、交互方式和协议，不是三个独立Agent。完整路径见[系统架构与执行机制](engineering.md)。

## Process表中的CP、P1、P与R

**CP（内容点）是评审根据原问题预先确定的必须回答点；Checklist需求是模型自己拆出的执行计划。** 同题各组共用CP，不因某组漏拆需求就减少它应回答的内容，也不因某组拆得更多就加分。

| 字段 | 如何理解 |
|---|---|
| **实际交付覆盖%** | 实际Final输入中的适用材料覆盖了多少CP；每点0／1／2分代表缺失或不适用／部分支持／直接覆盖。覆盖率=`100×CP得分之和÷(2×CP数)` |
| **P1 / 40** | 交付覆盖的40分制表示：覆盖百分数×0.4，例如50%对应20分；不是额外一项独立指标 |
| **P2 / 30** | State的事实忠实、证据绑定／适用范围、更新／缺口三项，各0／5／10分 |
| **P3 / 20** | Checklist的原题事实／范围和核心需求覆盖两项，各0／5／10分 |
| **P4 / 10** | 动作是否服务缺口，以及重复／停止是否合理；不按链路长度机械加扣分 |
| **P / 100** | P1＋P2＋P3＋P4的原始总分；保留信息收益与各项问题 |
| **R / 质量值／训练奖励** | 正常为P÷100；有未纠正重大非致命Process错误时乘一次0.49；致命或明确Process模型任务失败为0；工程不可信为`null`并留置 |
| **训练优势A** | 训练时`A=该条R−同题4条R的均值`，不除组内标准差；同条全部Process阶段共享它，尚未做逐步独立优势分配 |

`R1`中的R是需求ID前缀；评分列单独的`R`是质量值。二者没有数值对应关系。正确材料确已交付但State误读时，保留P1，另在P2处理错误；不会因为重大标签就自动把覆盖率清零。

**示意例子（非实验记录）：** 一题3个CP得分为2、1、0，则覆盖50%，P1为20。若P2／P3／P4为25／20／10，P为75，正常R为0.75；若有未纠正重大非致命Process错误，R为`0.75×0.49=0.3675`，覆盖仍为50%。

重大指核心实体、方向、范围、证据基础或任务被实质破坏；普通引用标签写错、一次无收益重复或单纯漏更新不自动判重大。取消高奖励仍保留不同轨迹的差异，不把所有重大错误都判零。尺度与扣分细节见[Process评分规则](evaluation.md#process怎么评分)和[跨基准评分口径](experiments/newbench_20261028/protocol.md)。

## 答案指标、失败和统计口径

| 术语 | 与Process分的区别 |
|---|---|
| **HB / HealthBench答案分** | `HB`是HealthBench简称。服务器qwen3.7-max按原题rubric逐项判断；得分为满足项权重之和除以正权重总和，可为负。表中“×100”只是换算尺度，不是准确率 |
| **MB / MedBrowseComp答案分** | `MB`是MedBrowseComp简称。替代Judge检查最终答案是否与参考语义等价，单条0／1、不设部分分；正确数÷有效评分数得到匹配准确率，不是逐字字符串完全一致检查 |
| **NA / NOT LISTED** | `NA`在本题集有特定参考约定，例如空独占期参考按作者规则归一为NA；不能泛指“我不知道”。`NOT LISTED`按题面要求处理。匹配这些答案不单独证明已经完成检索推理链 |
| **Final模块项目评分** | dev100按证据利用40%、问题相关性30%、忠实性20%、不确定性校准10%评分；没有已打开证据时证据利用不适用并重新归一。它与HB、MB和Process P／R是不同尺度 |
| **rubric / gold / Judge** | rubric是评分判据及权重；gold是指定训练目标答案；Judge是判分模型。Agent运行时不读取隐藏rubric或参考答案，Process审核也不拿Final答案分倒推P1 |

本项目的HB／MB使用Qwen替代裁判和登记的评分方案；本地Process与Final项目分来自离线AI审阅。**这些指标不是官方榜单成绩，也不是独立临床专家认证。** benchmark结果用于答案效果检查，不加入本轮Process-GRPO训练奖励。

| 状态／统计 | 阅读方式 |
|---|---|
| **complete／正常完成** | 程序取得并封存规定结果；不等于证据充分、答案正确或医学安全 |
| **Process失败** | Process模型输出合同错误等未恢复并终止；没有真实Final交付时P1为0，R为0，失败前材料保留诊断 |
| **Final-only失败** | Process已交付，但答案格式或引用等未通过；不自动把Process R置0，答案评分留空 |
| **工程失败／留置** | 数据损坏、身份不可信等无法归因到策略能力；R为`null`。训练时题组任一条为`null`则整组留置，不把未知损坏当模型零分 |
| **重大或Process失败，去重** | 两类记录的并集；一条同时满足只计一次。重大内容错误可以发生在完成轨迹中，不等于程序失败 |
| **完全重复Search额外动作** | 同题、同频道、大小写／空白规范化后query相同，首次之外的动作；可能命中缓存，不等于再次消耗外部API。该指标不涵盖所有语义换词冗余 |
| **胜／负／平** | 同题按指定指标比较。Process R和P1分别列胜负，不能互相替代；跨基准R差小于1e−8计平 |
| **有效配对／分母** | 答案只在双方均有评分的同题比较；失败另列、不伪造为零。Process全题比较保留明确模型失败R0，不能只挑成功配对 |
| **置信区间（CI）** | 本项目题目bootstrap反映固定本次生成／裁判结果下的题目抽样不确定性；不包含换seed重新生成或重复Judge的波动 |

**同配置**指固定Prompt、预算、检索实现、采样和Final等条件，四种Process仍会走不同路径，实时网页也可能变化。**固定输入**则指四个Final候选读取同一份冻结请求，隔离答案模块差异。前者不保证证据相同，后者不比较重新检索能力。

**参数冻结**表示相应权重不更新；**固定输入快照**表示保存实际请求并在后续比较中保持输入不变。保存请求文件不等于在线问答必须先执行导出，也不表示所有题目使用同一个输入。[交接与运行模式](engineering.md#handoff)

指标与错误需一起读：更高交付覆盖说明有用材料覆盖更多原题内容点，最终答案是否切题且忠实还需看Final及benchmark；更少轨迹失败说明执行更稳，不能单独代替内容评价。具体每题的支持、问题和失败见[逐题记录](records.md)。
