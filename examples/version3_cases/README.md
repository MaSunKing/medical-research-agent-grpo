# 版本三：两条真实轨迹，逐步查看Agent如何工作

[项目首页](../../README.md) · [系统设计](../../versions/process_final_sft/engineering.md) · [全部100题四组记录](../../versions/process_final_sft/records.md)

这里从已有四组评测中摘录两条GRPO25轨迹：一条展示完整证据交付，一条展示失败定位。它们用于解释系统行为，没有重新生成、补搜或重新评分；定性案例不替代100题的全部胜负和失败统计。

| 案例 | 可观察的行为 | 结果与限制 |
|---|---|---|
| [Q45：浅表伤口护理的证据交付](Q45_grpo25/README.md) | 2次Search、4次Browse、4次State更新；围绕敷料使用缺口续读并换源 | Process正常完成，实际交付覆盖100%；Final答案原分0.2885，不能把过程满分解释为医学答案满分 |
| [Q98：多跳检索中的动作合同失败](Q98_grpo25/README.md) | 找到目标试验；后续Browse两次绑定3项需求，超过单动作上限 | Process失败，未产生Final输入或答案；保留已发现内容及失败原因 |

每个案例提供原题、模型Checklist、全部已执行动作、State变化、短证据摘录、停止原因和既有四组评分。`CASE.json`保留模型原始阶段文本、状态变化及源文件哈希；Q45另附模型原始Final，Q98的Final明确为空。

公开内容经过字段筛选：不包含完整工具正文、系统请求、私人部署地址、凭据、gold、模型权重或整套运行数据库。少量证据原句带来源URL、片段ID、字符区间和文本哈希；完整原始记录保留于私有归档。原始输出中的拼写、重复和不完善判断不作润色。

本目录是benchmark输出的静态工程案例，不是面向具体患者的医疗建议。病例题面来自已公开的benchmark；分析用于区分证据交付、模型判断和最终答案质量。

离线核验：

```bash
python -B examples/test_version3_cases.py
```

该检查核验摘录结构、哈希、动作/State顺序、已有评分一致性和失败保留，不调用模型、检索或Judge。
